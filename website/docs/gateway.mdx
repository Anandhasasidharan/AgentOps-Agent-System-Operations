# Gateway

**WebSocket bridge** that connects NATS events to the dashboard in real-time.

## Purpose

The Gateway acts as the real-time communication layer:
- Subscribes to **NATS topics** (6 event types)
- Bridges events to **WebSocket clients** (dashboard)
- Enables live-updating dashboard without polling

## How It Works

```
NATS Events                    Gateway (port 8004)
┌──────────┐                  ┌─────────────────────┐
│ CB       │──────Topic──────→│                     │
│ Incidents│                  │  WebSocket Server   │
├──────────┤                  │                     │
│ SLO      │──────Topic──────→│  • Subscribe to     │
│ Alerts   │                  │    NATS topics      │
├──────────┤                  │  • Bridge to WS     │
│ Chaos    │──────Topic──────→│  • Auth via         │
│ Results  │                  │    API key param    │
└──────────┘                  └──────────┬──────────┘
                                         │
                                         ▼
                                  ┌──────────────┐
                                  │  Dashboard   │
                                  │  (WebSocket  │
                                  │   client)    │
                                  └──────────────┘
```

## Port

`8004` (default)

## Endpoints

| Method | Route | Purpose |
|--------|-------|---------|
| `GET` | `/health` | Health check |
| `WS` | `/ws` | WebSocket connection (query param: `api_key`) |

## Authentication

The dashboard server connects to the gateway with its configured API key. Browser clients connect to the dashboard’s same-origin `/ws` bridge using an HttpOnly session cookie, so the raw key is not embedded in browser URLs. Direct gateway clients still authenticate with the `api_key` query parameter.

## NATS Topics

The agentops-events package defines 6 topics for inter-service communication. The Gateway subscribes to all of them to forward events to the dashboard.
